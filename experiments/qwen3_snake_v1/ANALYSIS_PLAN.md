# Qwen3 Snake v1: prospective analysis plan

**Status: prepared and unexecuted.** No model weights were downloaded and no model-backed calls or games were run to prepare this protocol. This is an additive experiment for [issue #1](https://github.com/cameronbergh/clef-snake-quantization/issues/1). It does not revise, extend the sample size of, or pool scores with the published CLEF discovery experiment.

The machine-readable choices are in [protocol.json](protocol.json), the once-generated environments in [seed-manifest.json](seed-manifest.json), and the fixed order in [schedule.json](schedule.json). The publication freeze manifest binds these files and the adapter to their hashes. A later execution record must bind exact model artifacts, binary, launch arguments, hardware, and the published freeze before the first model request. Preparation is not permission to download, load, or run a model.

## Question and scope

On this specified Snake task, how do Q4_K_M and Q2_K backbone recipes, each retaining BF16 tied input/output weights, change the capped food score relative to a BF16 GGUF generated from the same official Qwen3-4B-Instruct-2507 checkpoint, with all three run through the same pinned standard llama.cpp runtime and action interface?

Variant display labels are **Q4_K_M backbone + BF16 tied I/O** and **Q2_K backbone + BF16 tied I/O**. The checkpoint ties token embeddings to its lexical output projection. Keep that shared tensor in BF16 for every variant and verify its exact equality after conversion/quantization; any separately materialized output tensor must also remain BF16 and equal. These are controlled mixed recipes, not off-the-shelf whole-model Q4_K_M/Q2_K files. This is a prospective within-model comparison. Qwen is a supported non-thinking text-generation model; it does not use CLEF's custom decision head. Its constrained JSON action interface is explicitly a different protocol from CLEF's head argmax. Absolute Qwen-versus-CLEF comparisons are descriptive and cannot isolate the model family from interface and execution differences. Neither the model choice nor this protocol was selected using new Qwen game scores.

BF16 GGUF load and generation compatibility remains unverified. Failure to support that baseline stops this version. An F16 replacement, different runtime, changed template, or changed response constraint requires a new protocol version and freeze before collecting any game scores. Do not silently substitute one.

## Fixed design

- Thirty fresh environment seeds are the paired sample units. Each is used once for each of `bf16`, `q4-k-m`, and `q2-k`: 90 planned games. All 30 main seeds and six separate preflight seeds were written once from `secrets.token_hex(16)` without inspecting food positions, trajectories, or model output. They are mutually disjoint and disjoint from every published seed manifest checked at preparation.
- The six permutations of three variants each occur five times. Execute the saved 90-entry order exactly. Thus each variant occurs ten times in each within-seed position. The order is fixed and balanced, not claimed to be a randomized treatment assignment.
- Only one variant is loaded at a time, and only one inference request may be active. Unload/reload between consecutive scheduled games as necessary. Do not batch all games of one model to reduce loading costs. Log setup duration separately from gameplay latency. No interactive or other benchmark model calls may overlap.
- Keep `clef_snake.game.Game`: 12×12 board; body `[[5,6],[4,6],[3,6],[2,6]]`; initial direction right; original factual features and question; same SHA256 food-event priorities and move semantics. All four actions remain selectable. No solver, safe-action mask, override, retry, or sampling is introduced.
- Each game ends at the first collision or after 500 successful moves. Snake waits for one response before applying one move; there is no gameplay wall-clock budget. A collision request is an attempt but not a successful move. The maximum is 500 requests per game and 45,000 main-game requests. A game capped alive stays labelled capped alive.
- Greedy constrained generation uses the exact fresh system/user messages, schema, token limit, decoding controls, and response-validation rules fixed in `protocol.json` and the bound adapter. No previous turn or previous game history is sent. Do not tune prompts, features, decoding, quantization recipe, or the game using main scores.

The prospective server configuration is fixed: context 8,192 tokens; batch and microbatch 512 tokens; eight threads for generation and batch work; one parallel slot; all model layers on Metal; flash attention on; F16 K/V cache; automatic fitting off; RAM prompt cache zero; context shifting and automatic warmup disabled; native Jinja template processing enabled; loopback host `127.0.0.1`, port `8781`, alias `snake-qwen3-v1`. The request timeout is 120 seconds. Installed help confirms option availability, not successful model execution. Verify the effective settings and exact binary/template hashes before calls; unsupported settings stop this version without a fallback. A timeout is a technical failure, never a clock penalty or collision.

Model acquisition/conversion must first pass the storage gate on the external Models storage partition identified in the resource plan, with the exact mount identity, destination and free space checked and no fallback to internal storage. Converter provenance remains a separate prerequisite; pin the actual converter and dependencies, then verify the generated BF16 artifact and retained tied input/output tensors. No acquisition or conversion has occurred in this preparation.

The six preflight seeds permit exactly 18 initial-state-only requests, one per seed and variant, after separate authorization. Preflight checks loading, context fit, the inherited template, response constraint, parsing, and evidence logging. It performs no scored game rollout and no outcome-based selection. Retain every response, including errors. A failure stops preflight; changes require an explicitly versioned amendment and a fresh freeze, not hidden retries. Preflight and main seeds never exchange roles.

## Endpoints and reporting

The primary outcome is **observed food collected by collision or the 500-successful-move cap**. This defines the capped-score estimand; food that a capped game might collect later is unknown. For each quantization, the primary contrast is the mean of its 30 paired food-score differences versus BF16. Report food units first; any percentage change is secondary and is undefined if the baseline mean is zero.

Publish every planned seed/variant row, including not-started and failed rows. For valid completed games report food, successful moves, attempted requests, collision/cap status, final state and evidence identifiers. Show paired scores and differences, mean/median/range, wins/ties/losses against BF16, and cap counts per variant. The 90 executions and individual turns are not independent samples. Do not pool this set with the earlier 15 discovery seeds.

Technical failures are not collisions and are not zero-food results. Store a separate failure category, the complete offending raw request/response or error, and the last valid state. Partial food is diagnostic only; the outcome field is `null`/NA. Retain rows for remaining planned games as not started. Never discard a failure because the model had a low score. Parsing/grammar errors, truncation, server errors, timeout, context overflow, model mismatch, wrong configuration, evidence-write failure, or a concurrent inference client stop the campaign on the first occurrence. No retry of that game or automatic fallback is allowed.

A stopped campaign cannot be called a completed 30-seed confirmation. Complete-pair summaries may be shown transparently as incomplete descriptives, alongside all failures and missing rows; they do not inherit the planned inferential claim. Repair requires a new version or clearly identified separately frozen phase that retains the failed evidence. Do not silently resume, combine repaired phases, or make complete-case inference look intention-to-run.

## Fixed uncertainty calculations

Run these planned calculations only on a technically complete set of all 90 valid scored games. The comparison family has exactly two members, in order: Q4_K_M backbone + BF16 tied I/O minus BF16, then Q2_K backbone + BF16 tied I/O minus BF16. Short variant IDs below retain those full recipe definitions.

1. Resample all 30 paired seed rows together with replacement, 100,000 replicates using NumPy `Generator(PCG64(20261006))`. Use the same sampled row indices for both contrasts. Report unadjusted 2.5th and 97.5th percentiles of each bootstrap mean difference using NumPy's `linear` quantile method. Preserve the original point estimate and complete seed table. These are paired percentile intervals, not guaranteed coverage or simultaneous family intervals.
2. Report a two-sided paired sign-flip test for each contrast using the absolute sum of the integer paired differences as the statistic. Omit zeros when constructing sign flips. With at most 20 nonzero differences, enumerate all `2**n` sign assignments and count statistics greater than or equal to the observed value; divide by the number of assignments. With zero nonzero differences set p=1. With more than 20 nonzero differences, use 1,000,000 independent uniformly random sign vectors and the add-one p-value `(extreme + 1) / (1_000_000 + 1)`.
3. Use one NumPy `Generator(PCG64(20261007))` for Monte Carlo sign flips, processing the two contrasts in the order above; exact branches consume no random draws. For each replicate draw a vector in nonzero seed-manifest order using `rng.integers(0, 2, size=n, dtype=np.int64)`, mapping zero to -1 and one to +1. Batch implementations must preserve that flat draw sequence. Publish the method, nonzero count, extreme count, and Monte Carlo resolution/uncertainty. Do not change replicate count after seeing a borderline result.
4. Apply Holm adjustment to the two raw sign-flip p-values: sort ascending with fixed comparison order breaking ties; adjusted first p is `min(1, 2*p_first)`, adjusted second is `max(adjusted_first, p_second)`. Report raw and adjusted values. If discussing a threshold, predeclare familywise alpha=0.05 and use adjusted values. Positive benefit additionally requires a positive observed mean contrast; a significant negative contrast is harm for this capped-score endpoint.

Sign flipping assumes exchangeability of the signs under the null (or symmetric paired differences). The balanced deterministic execution order is not treatment randomization that establishes that assumption. These tests do not prove a causal pure-bitwidth effect: mixed tensor recipes, numerical kernels, token logits and trajectory feedback all change, and time/hardware effects can remain. The paired bootstrap also relies on the saved seeds representing the target environment population. Thirty seeds were chosen as a bounded practical validation size, without a power guarantee. Failure to reject is not evidence of equivalence; no noninferiority margin or equivalence test is planned.

## Secondary observations and integrity

Latency is descriptive: save request wall time, prompt/generated token counts, exposed server evaluation timings, model load time, and available memory measurements separately. Gameplay paths and prompt lengths differ, so pooled latency cannot establish a clean throughput gain. Do not penalize slower responses in the score. A timeout is an operational technical failure, not a Snake loss. Caps censor survival and ultimate food score beyond the defined cap; make no uncapped survival claim.

Record full ordered messages, exact serialized user content, complete raw responses and parsed actions, per-turn state transitions, food events, model/artifact/runtime hashes, configuration, seed/game positions, request identifiers, and terminal outcomes. Evidence must permit independent reconstruction using the unchanged game implementation and reconciliation to independent server logs. Export through an allowlist, excluding local personal paths and secrets; retain hashes and license/source provenance. An auditor for this new schema must exist and pass before the campaign is declared complete or published as valid evidence.

First-divergence or mechanism analysis, individual seeds, additional models, extra precision recipes, altered caps and other tasks are secondary exploratory work requiring explicit labelling; they cannot replace the two primary contrasts or justify stopping early. Future designs informed by these results need new held-out environments and a new freeze. Never reinterpret a candidate-source or feasibility check as a model result.
